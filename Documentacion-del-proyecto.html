Contexto del Proyecto y Arquitectura

El sistema se integra directamente a WhatsApp, permitiendo a los usuarios enviar fotografías de recibos y documentos financieros de forma rápida y ubicua. El agente actúa como el motor principal que, mediante visión artificial y procesamiento del lenguaje natural (NLP), extrae los datos relevantes de las imágenes y los estructura en la base de datos de la organización.

La arquitectura del ecosistema está concebida bajo un enfoque de microservicios, lo que garantiza alta escalabilidad y robustez frente a un gran volumen de transacciones.

Visión Artificial & NLP

🛡️

Detección de Anomalías

El flujo incorpora algoritmos orientados a identificar posibles fraudes y errores en los comprobantes, sumando una vital capa de seguridad y precisión financiera.

Paso a Paso del Flujo (n8n)

A continuación, el detalle lógico de cómo operan los ~300 nodos definidos en la automatización para crear una experiencia bidireccional perfecta.

  • Recepción del Mensaje y Autenticación

    Inicia el flujo a través de un webhook de WhatsApp. Se conecta inmediatamente a Google Sheets ("Numeros Autorizados") para validar credenciales asegurando que el número del emisor exista en la base corporativa y bloqueando consumos fantasmas en las APIs de los LLM.

  • Análisis de Imágenes y OCR (Extracción Inteligente)

    Al recibir un archivo multimedia, el sistema descarga la foto del recibo y ejecuta una llamada a la Inteligencia Artificial. Un nodo de Código especial filtra la respuesta con expresiones regulares asegurando el formato JSON puro de los campos: Fecha, RUT, Proveedor, Detalle de gasto y Monto.

  • Aprobación y State Machine Conversacional

    Dado que WhatsApp no preserva el contexto nativamente como un chat interactivo, el flujo utiliza una hoja temporal "Memoria Mensajes" como base de datos de estado. Envía los datos extraídos al usuario por WhatsApp para su aprobación (Si/No).

  • Clasificación e Información Manual

    Mediante una amplia red lógica de nodos Switch, el agente solicita categorización interactiva. Cuestiona sobre el Tipo de Documento, Tipo de Rendición (Caja chica, Fondo por rendir o Reembolso) y la proveniencia. Si algún campo falló en la extracción, solicita ingresar el dato faltante reactivando el trigger y consultando el "Estado" desde Google Sheets iterativamente.

  • Consolidación y Registro Oficial

    Validado cada punto, sube el respaldo físico a Google Drive generando un enlace público. Determina la hoja final correspondiente a la rendición, inserta la metadata estructurada limpia y borra los archivos/filas de estado temporal para mantener la higiene de la base de datos. Finaliza con un mensaje confirmatorio al usuario.

An Artificial Intelligence system designed to optimize, centralize, and automate the management of corporate expense reports, orchestrated through n8n and fully accessible via WhatsApp.

Project Context & Architecture

The system integrates directly with WhatsApp, allowing users to quickly and ubiquitously send photographs of receipts and financial documents. The agent acts as the core engine which, through computer vision and natural language processing (NLP), extracts relevant data from the images and structures them into the organization's database.

The ecosystem's architecture is built on a microservices approach, ensuring high scalability and robustness against a large volume of transactions.

👁️

Computer Vision & NLP

Utilization of Foundational Models (Google Gemini / OpenAI) for optical character recognition and semantic extraction of key transactional fields.

🛡️

Anomaly Detection

The workflow incorporates algorithms aimed at identifying potential fraud and errors in receipts, adding a vital layer of financial security and accuracy.

⚡

Scalable Microservices

Developed on the n8n platform, allowing orchestration of modular APIs (WhatsApp Graph API, Google Drive, Google Sheets, LLMs).

Step-by-Step Flow (n8n)

Below is the logical detail of how the ~300 nodes defined in the automation operate to create a seamless bidirectional experience.

  • Message Reception & Authentication

    The flow starts through a WhatsApp webhook. It immediately connects to Google Sheets ("Allowed Numbers") to validate credentials, ensuring the sender's number exists in the corporate database and blocking ghost consumptions on the LLM APIs.

  • Image Analysis & OCR (Smart Extraction)

    Upon receiving a media file, the system downloads the receipt photo and executes a call to Artificial Intelligence. A special Code node filters the response with regular expressions ensuring a pure JSON format of the fields: Date, Tax ID, Provider, Expense Detail, and Amount.

  • Approval & Conversational State Machine

    Since WhatsApp does not natively preserve context as an interactive chat, the flow uses a temporary sheet "Message Memory" as a state database. It sends the extracted data to the user via WhatsApp for approval (Yes/No).

  • Manual Classification & Information

    Through a vast logical network of Switch nodes, the agent requests interactive categorization. It asks about Document Type, Expense Type (Petty Cash, Fund to be Rendered, or Reimbursement), and origin. If any field failed in extraction, it requests the missing data, reactivating the trigger and querying the "State" from Google Sheets iteratively.

  • Consolidation & Official Registration

    Once everything is validated, it uploads the physical backup to Google Drive generating a public link. It determines the final sheet corresponding to the expense, inserts the clean structured metadata, and deletes the temporary state files/rows to maintain database hygiene. It ends with a confirmation message to the user.
